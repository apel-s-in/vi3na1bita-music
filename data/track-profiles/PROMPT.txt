Ты анализируешь один музыкальный трек и создаёшь TrackProfile.

ВХОДНЫЕ ДАННЫЕ

UID: {{UID}}

Тебе переданы:

1. Музыкальный файл.
2. Точный текст песни, если он существует.
3. data/taxonomy.json.
4. data/track-profile-vocabulary.json.
5. data/track-profiles/track-profile.template.json.

ФОРМАТ ОТВЕТА

Верни ровно один синтаксически корректный JSON object.

Не используй Markdown.
Не добавляй пояснения.
Не добавляй комментарии.
Не добавляй поля, отсутствующие в шаблоне.
Не удаляй поля шаблона.
Сохраняй порядок полей шаблона.

ЯЗЫКИ

Все machine ID записываются только на английском языке в snake_case.

Это относится к:

- taxonomy-ключам;
- instrumentation;
- vocalRoles;
- vocalDelivery;
- arrangementTags;
- productionTags;
- tempoClass;
- key;
- mode;
- timeSignature;
- language;
- narrative.type;
- narrative.perspective;
- status.

Свободный текст разрешён только в полях с суффиксом _ru.

Весь свободный текст должен быть написан грамотно и только на русском языке.

Запрещено смешивать английские слова с русским текстом.

Нельзя писать:

"Композиция built на контрасте"
"Плотный синтезаторный басист"
"Трек построена"

Нужно писать:

"Композиция построена на контрасте"
"Плотный синтезаторный бас"
"Трек построен"

ДОСТОВЕРНОСТЬ

Анализируй фактическое звучание аудиофайла, а не название трека.

Не выдумывай неизвестные значения.

Если значение определить нельзя:

- BPM = null;
- tempoClass = null;
- key = null;
- mode = null;
- timeSignature = null;
- loudnessLufs = null;
- dynamicRange = null;
- соответствующий technicalConfidence = 0;
- vocalPresence = null;
- sparse object = {};
- строковое описание = "";
- массив = [].

Не угадывай технические значения ради заполнения.

confidence находится в диапазоне 0..1.

musicAnalysis.confidence отражает уверенность в музыкальном анализе.

lyricAnalysis.confidence отражает уверенность в анализе текста.

Если точный текст не предоставлен:

- не придумывай слова;
- не создавай цитаты;
- не создавай подробный сюжет;
- снижай lyricAnalysis.confidence;
- сохраняй неизвестные lyric-поля пустыми.

Правильно:

ТЕХНИЧЕСКИЕ ОЦЕНКИ

loudnessLufs и dynamicRange разрешено оценивать по аудиофайлу.

loudnessLufs:

- оценка интегральной громкости в LUFS;
- допустимый диапазон -40..0;
- не выдавай оценку за лабораторное измерение;
- если надёжная оценка невозможна, используй null.

dynamicRange:

- оценка динамического диапазона в децибелах;
- допустимый диапазон 0..30;
- если надёжная оценка невозможна, используй null.

technicalConfidence содержит:

- bpm;
- key;
- loudnessLufs;
- dynamicRange.

Каждое значение technicalConfidence находится в диапазоне 0..1.

Интерпретация:

0 = значение неизвестно;
0.25 = слабая предположительная оценка;
0.5 = правдоподобная, но непроверенная оценка;
0.75 = высокая уверенность;
1 = практически однозначно.

Если техническое значение равно null, его technicalConfidence обязательно равно 0.

Не завышай technicalConfidence только потому, что поле заполнено.

РАЗМЕР

timeSignature берётся только из track-profile-vocabulary.json.

Запрещено:

"4/4"

Правильно:

"4_4"

ИНСТРУМЕНТЫ

instrumentation является sparse object с весами 0..1.

Разрешены только ключи из track-profile-vocabulary.json.instrumentation.

Вокал не является инструментом.

Запрещено помещать в instrumentation:

male_vocals
female_vocals
мужской вокал
женский вокал
choir_vocals

Вокальные признаки записываются в vocalRoles и vocalDelivery.

Не дублируй общий и частный инструмент:

- если уверенно определена trumpet, не добавляй brass_section;
- brass_section используй, когда слышна секция, но точный состав не определяется;
- если определён synth_bass, не добавляй bass_guitar без фактически слышимой бас-гитары;
- не добавляй абстрактный sound_effects.

ВОКАЛ

vocalRoles содержит только значения из vocabulary.vocalRoles.

vocalDelivery содержит только значения из vocabulary.vocalDelivery.

vocalPresence:

0 = вокала нет;
1 = вокал почти постоянно доминирует;
null = определить нельзя.

АРАНЖИРОВКА И ПРОДАКШН

arrangementTags содержит только vocabulary.arrangementTags.

productionTags содержит только vocabulary.productionTags.

Свободное описание аранжировки записывается только в arrangementDescription_ru.

Свободное описание звучания записывается только в productionDescription_ru.

Не используй рекламные оценки:

"идеальный"
"лучший"
"невероятный"
"коммерческий хит"

LYRIC ANALYSIS

summary_ru кратко передаёт фактический смысл песни.

keywords_ru содержит только русские значимые слова и фразы.

entities_ru содержит только явно названные сущности, собственные имена, персонажей, организации или конкретные географические объекты.

Не помещай обычные образы и нарицательные места в entities_ru.

scenes_ru содержит только действительно различимые сцены.

narrative.type берётся только из vocabulary.narrativeTypes.

narrative.perspective берётся только из vocabulary.narrativePerspectives.

narrative.arc_ru и narrative.characters_ru пишутся только по-русски.

TAXONOMY

В finalProfile разрешены только ключи из соответствующих групп taxonomy.json:

genres
styles
moods
themes
use_cases
time_of_day
axes
content_warnings

warnings использует ключи taxonomy.groups.content_warnings.items.

Все sparse-веса должны быть числами от threshold_store до 1.

Не сохраняй признаки ниже threshold_store.

Не добавляй родительский жанр автоматически только потому, что указан поджанр.

Например, alternative_rock не требует автоматического добавления rock.

Высокие веса 0.75 и выше используй только для доминирующих признаков.

AXES

finalProfile.axes должен содержать все оси шаблона.

Каждая ось является числом 0..1.

0 означает уверенное отсутствие признака.

Не используй null для axes.

WARNINGS

warnings описывает только чувствительный контент.

Грусть, драматичность, напряжение и мрачное звучание сами по себе не являются warning.

PRESENTATION

tagline_ru — короткая характеристика трека.

one_liner_ru — одно честное предложение о музыке и смысле.

mini_description_ru — два или три коротких предложения.

Не создавай несуществующие цитаты.

Не упоминай рекомендации, популярность или другие треки.

ФИНАЛЬНАЯ ПРОВЕРКА

Перед ответом проверь:

1. JSON синтаксически корректен.
2. uid содержит фактический UID.
3. В JSON нет "{{", "}}" и "__TEMPLATE__".
4. Нет запрещённых полей.
5. Нет названия модели и даты.
6. Нет title, album, albumTitle, durationSec и trackVersion.
7. Все machine ID существуют в taxonomy или vocabulary.
8. Все machine ID написаны на английском языке в snake_case.
9. Все поля с суффиксом _ru написаны только по-русски.
10. В русских предложениях нет случайных английских слов.
11. instrumentation не содержит вокал.
12. Нет дублирующих инструментов.
13. key не содержит лад.
14. timeSignature использует подчёркивание.
15. Sparse-веса не ниже threshold_store.
16. Все axes заполнены числами 0..1.
17. loudnessLufs равен null или находится в диапазоне -40..0.
18. dynamicRange равен null или находится в диапазоне 0..30.
19. technicalConfidence содержит bpm, key, loudnessLufs и dynamicRange.
20. Для null технического значения соответствующая confidence равна 0.
21. Нет relations и похожих UID.
22. Ответ содержит только один JSON object.
